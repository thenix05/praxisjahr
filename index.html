Prüfungstrainer Waffentragen

HTML, JavaScript, eine Datei, 106 Fragen

live ausprobieren

thenix05.github.io/waffentrag-trainer

Aufgabe. Ich musste die Prüfung Waffentragen bestehen und wollte die Fragen üben statt sie nur zu lesen.

Entscheidung. Eine einzelne HTML-Datei ohne Framework, damit sie überall ohne Installation läuft. Ein falscher Klick zählt sofort als nicht gewusst, sonst klickt man sich durch. Der Fortschritt liegt im Browser, damit man zwischendurch aufhören kann.

Grenze. Die richtigen Antworten stammen aus dem öffentlichen Fragenkatalog des fedpol, die falschen Vorschläge habe ich selbst ergänzt. Ohne Konto gibt es keine Statistik über mehrere Geräte.

Nächster Schritt. Die Fragen aus der HTML-Datei in eine JSON-Datei auslagern, damit Korrekturen ohne Codeänderung möglich sind.

function toggle(i){

Texterkennung mit Tesseract

C#, .NET, Konsolenanwendung, OCR

Code ansehen

Aufgabe. Verstehen, wie zuverlässig Texterkennung bei unterschiedlichen Vorlagen wirklich ist.

Entscheidung. Tesseract über das NuGet-Paket statt eines Webdienstes, damit nichts hochgeladen wird. Bildpfad, Sprachdaten und Sprache kommen als Argumente, damit das Programm nicht nur auf meinem Rechner läuft.

Grenze. Beim Flyer liegt die Zuverlässigkeit deutlich höher als beim Kontrollschild. Eine Vorverarbeitung der Bilder fehlt, deshalb bleibt das Schild der schlechteste Fall.

Nächster Schritt. Kontrast anheben und zuschneiden, bevor das Bild an Tesseract geht, und die Werte vorher und nachher vergleichen.

Ausgabe des Programms bei einem Kontrollschild. Beim Flyer der Schule liegt die Zuverlässigkeit deutlich höher. Die Testbilder zeigen die Musternummer 999999 und enthalten keine echten Halterdaten.

Minimal API mit MongoDB

C#, .NET, MongoDB, Docker Compose

Code ansehen

Aufgabe. Eine kleine Web-API mit Datenbank, die auf jedem Rechner mit einem einzigen Befehl startet.

Entscheidung. Minimal API statt Controller, weil die Anwendung dafür zu klein ist. Datenbank und Anwendung liegen zusammen in einer docker-compose-Datei, damit niemand erst eine Datenbank installieren muss.

Grenze. Keine Authentifizierung und keine Tests. Das Projekt zeigt den Aufbau, nicht den Betrieb.

Nächster Schritt. xUnit-Tests für die Endpunkte und die Zugangsdaten aus der compose-Datei in Umgebungsvariablen auslagern.

services:
  mongodb:
    image: mongo
    ports: ["27017:27017"]
    volumes: [mongodb_data:/data/db]

  webapi:
    build: { context: ./WebApi }
    ports: ["5001:5001"]
    depends_on: [mongodb]
